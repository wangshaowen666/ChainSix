# 项目设计规范

## 1. 热更方案

项目采用 HybridCLR（华佗）热更新方案，业务逻辑全部由 C# 编写。同时接入了 xLua，但仅实现了 Lua 启动的入口逻辑，不作为主要业务开发语言。

## 2. 程序集划分

项目划分为四个程序集，按依赖关系自底向上排列：

| 程序集 | 说明 | 是否可热更 |
|---|---|---|
| **CoreFramework** | 核心框架层，包含底层基础设施（FSM、ClassPool、UpdateMgr、Variable 等） | 否 |
| **Launch** | 启动层，包含启动流程、登录界面、启动配置等项目特定逻辑 | 否 |
| **Framework** | 框架层，包含可热更的管理器（Res、Event、Timer、Scene、Lua、ObjectPool 等） | 是 |
| **Game** | 游戏业务层，包含具体业务实现（面板、实体、战斗逻辑等）及数据表（Luban 生成代码、DataTableMgr） | 是 |

依赖方向：`CoreFramework <- Launch <- Framework <- Game`

新项目时的替换策略：
- CoreFramework：不改动
- Launch：替换启动流程和配置
- Framework：框架代码不改动
- Game：按需清理或保留。Luban 导出表（DataTableMgr 及生成代码）和依赖它的框架逻辑（UIMgr、EntityMgr 等）随数据表结构调整，具体面板、实体、战斗逻辑等业务代码按项目需求清理重写

## 3. 类的设计原则

项目不使用单例类。功能模块按是否有状态分为三类：

### 3.1 有状态管理类

需要统一管理初始化顺序、场景切换清理等生命周期逻辑的模块，继承 `ManagerBase`，由 `FrameworkMgr` / `GameMgr` 统一持有和管理。

```csharp
public class TimerMgr : ManagerBase
{
    public override void OnSceneExit(int sceneTp) { ... }
}
```

示例：TimerMgr、EventMgr、ResMgr、ObjectPoolMgr 等。

### 3.2 无状态静态类

无需生命周期管理、全局唯一的工具或基础设施，声明为静态类。

```csharp
public static class ClassPool { ... }
public static class Log { ... }
public static class UpdateMgr { ... }
```

工具类脚本统一命名为 `XXXUtil`：

```csharp
public static class ParseUtil { ... }
public static class FileUtil { ... }
```

### 3.3 普通实例类

会存在多个实例化对象、生命周期跟随创建者的模块，声明为以功能命名的普通类，提供静态 `Create` 方法进行实例化。

```csharp
public class Fsm
{
    public static Fsm Create<T>(params T[] states) { ... }
}
```

示例：Fsm、FsmState、Variable 等。

## 4. 异步方案

项目不使用协程（Coroutine），所有异步逻辑通过 UniTask 实现。定时器、延迟执行、重复执行等需求统一使用 TimerMgr 提供的接口。
