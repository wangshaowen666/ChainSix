# 六连珠对战玩法开发任务清单

> 范围：客户端 + 服务器复用改造 + 微信小游戏平台接入。**两种模式**：好友实时对战（帧同步，`FrameSyncMgr` 驱动，v1 核心）+ 人机对战（`LocalDriver` 驱动 + AI 输入提供者）。
> 选题：《世界游戏大全51》「6连珠益智」的差异化改造——Puyo 式双棋盘垃圾子对战（各下各的棋盘、六连向对方投垃圾子、堆过高度线即负）。本项目为**计划正式上线**的微信小游戏（广告变现）；塔防/吸血鬼为验证项目。
> 姊妹文档：`服务器开发流程.md`（帧同步基建/房间/结算/待办清单）、`客户端项目架构梳理.md`（框架与复用范式）、`吸血鬼幸存者玩法开发任务清单.md`（LocalDriver/插值/UI 范式来源）。

## 玩法定义与范围

**核心循环**：双方各一块竖屏棋盘；出子队列供颜色（预览 3 颗），玩家点列落子（可按住加速下落抢节奏）；同色 **6 连**（横/竖/斜）消除，上方棋子重力下落可触发**连锁**；消除向对方棋盘投放**随机色垃圾子**（单线 3 颗、双线/十字 5 颗、连锁每级 +2，数值进表）；棋盘堆过高度线即负。金字塔/六角构型（一次落子触发多线）是技巧上限。

**MVP 范围**

| 维度 | 范围 |
| --- | --- |
| 模式 | 好友实时对战（微信分享进房，v1 核心）+ 人机对战（AI 三档，无关卡制） |
| 人数 | 2（对战双方各一块棋盘） |
| 单局时长 | 2~4 分钟（调参 KPI） |
| 棋盘 | 7 列 × 12 行（上 2 行危险区），竖屏 |
| 颜色 | 5 色 + 队列预览 3 颗（颜色数是难度总开关） |
| 消除 | 同色 6 连（横/竖/斜）+ 重力连锁 |
| 操作 | 点列落子 + 按住加速 |
| 变现 | 激励视频（开局护盾/结算星尘双倍）+ 插屏（仅结算后，日 ≤3） |
| 平台 | 微信小游戏 |

**明确不做（v1）**：匹配系统（服务器 MatchMaker 已有，DAU 起来后开启 + 机器人填充）、段位赛季、皮肤商店、人机关卡/道具/障碍（豆包方案整体进 v2 backlog）、异步挑战、好友周榜（开放数据域，后置）、单机闯关。

## 总体架构决策（先定后做）

1. **逻辑/表现分离**：`SixLineLogic` 纯 C#（零 UnityEngine 依赖），下落/消除/连锁/垃圾子全在逻辑层确定性演算；`SixLineView` 只做视图对账/插值/特效/UI。
2. **模式-驱动映射**：人机 = `LocalDriver`（真人触摸输入 + AI 输入提供者）；好友对战 = `FrameSyncMgr`（网络帧输入）。同一 `Tick(frame, inputs)` 双驱动零改动。
3. **服务器零玩法逻辑**：纯转发 + 房间 + 结算记录（复用塔防链路）。作弊风险 v1 可接受（好友对战无利益对抗）；段位期补服务器影子重演（服务器文档 A3）。
4. **AI = 确定性输入提供者**：AI 决策 = 对局种子驱动的 `XRng` + 启发式评估，输出与真人同形状 op；人机/后续匹配机器人填充共用一套。
5. **数值全配置化**：棋盘尺寸/颜色数/下落速度/垃圾公式/连锁加成全进 Luban 表，灰盒调参零改代码。
6. **输入协议**：离散 op（落子=选列、加速）；加速协议形状（独立 op vs 落子附带标志）阶段 1 拍板；proto 字段号只追加。
7. **连锁在 Tick 内同步结算**：消除 → 重力下落 → 落定复扫，单逻辑帧内递归到稳定，保证确定性与 StateHash 简单。

## 开发约定（必须遵守）

### 确定性纪律（`SixLineLogic` 及下属结构禁用）

| 禁用 | 替代 |
| --- | --- |
| float / double | `Fix`；常量 `Fix.FromDouble(x)` 仅限初始化 |
| UnityEngine.Random / System.Random | `XRng` + 对局种子（联机种子服务器 `StartGamePush` 下发） |
| Time.deltaTime / Time.time | 逻辑帧号计数换算 |
| Dictionary 遍历 / LINQ / foreach 闭包 | 有序 List、for 循环 |
| Tick 内 new / 装箱 / 字符串拼接 | 池化、预分配 |

### 项目规范

同《客户端项目架构梳理.md》第十节：日志统一 `Log`、热更脚本只挂 Addressables 资源、Update 走 `CoreMgr.Update`、新 UI/表/实体走 ToolBox 既有流程、生成物勿手改、proto 字段号上线后只能追加。

## 阶段 1：灰盒核心对局（本地双人同机）

**目标**：无美术图元跑通完整对局——双棋盘、落子、六连消除、连锁、垃圾子、胜负，数值全部进表。**本阶段唯一 KPI：调到"单局 2~4 分钟、六连能成、连锁有惊喜"，并拍板 6 连 vs 5 连。**

- [ ] 1-1 模式接入：`BattleMode.SixLine` + `BattleMgr.EnterBattle` 分支 + `SixLineLogic`/`SixLineView` 空骨架（LogicFrameMs=50ms 常量、FNV-1a StateHash、目录 `Game/Battle/SixLine/`）
- [ ] 1-2 棋盘与出子：7×12 网格（含危险区）、颜色枚举、`XRng` 出子队列（预览 3）、当前子固定步长下落（`Fix` 速度）+ 加速落地、触底入格
- [ ] 1-3 消除与连锁：6 连横/竖/斜扫描 → 消除 → 重力下落 → 落定复扫（连锁计数），单 Tick 内递归结算到稳定
- [ ] 1-4 垃圾子投放：消除向对方棋盘投随机色子（单线 3 / 双线十字 5 / 连锁每级 +2，落点列 `XRng`）
- [ ] 1-5 胜负判定：堆过高度线 GameOver（区分胜负方）
- [ ] 1-6 灰盒表现：图元棋盘/棋子（ViewMats URP 工厂 + 真机 shader 兜底）、己方棋盘大/对方棋盘小的竖屏布局、点列落子 + 按住加速、下落插值（复用 VS 双缓冲）、调试 HUD（帧号/队列/连锁数）
- [ ] 1-7 本地双人对战：`LocalDriver` + 双输入源（调试用键盘 P1/P2 或同屏分区触摸）
- [ ] 1-8 调参表：Luban 建表（棋盘尺寸/颜色数/下落速度/加速行为/垃圾公式/连锁加成）
- [ ] 1-9 调参与拍板：按 KPI 调参；输出 **6 连 vs 5 连**结论及颜色数、棋盘尺寸定稿

**验收**：本地双人可完整对局；同种子重放 StateHash 全程一致；数值全部来自表；Profiler 确认 Tick 零 GC。

## 阶段 2：人机对战（AI 输入提供者）

**目标**：单人可随时开局，三档难度体感差异明显；AI 确定性可重放（为匹配机器人铺路）。

- [ ] 2-1 AI 输入提供者：启发式评估（完成线进度优先、双线/金字塔构型加分、高度惩罚、噪声），输出与真人同形状 op；决策随机全部走对局种子 `XRng`
- [ ] 2-2 三档难度：落子思考间隔 × 评估噪声幅度（简单接近随机，困难会主动做双线构型）
- [ ] 2-3 人机模式接入：入口 + `LocalDriver` 双输入源（触摸 + AI）+ 胜负结算
- [ ] 2-4 AI 确定性验证：同种子重放 AI 决策序列一致

**验收**：三档难度可感知；AI 不卡死不犯规；同种子重放一致。

***

## 阶段 3：帧同步联机（好友对战）

**目标**：复用塔防帧同步链路跑通双端实时对战；编辑器双开 → 真机验证。

- [ ] 3-1 双驱动切换：`SixLineView` 改由 `FrameSyncMgr.OnFrame` 驱动（`SixLineLogic` 零改动）；种子/起始帧/参战玩家读 `StartGamePush`
- [ ] 3-2 输入协议：PlayerInput 落子/加速 op 定稿（proto 追加字段号 + `net_common.proto` MsgType）；服务器操作校验按模式适配（TD 坐标范围校验不适用离散 op）
- [ ] 3-3 房间流程：`RoomMgr` 建房/就绪/开局/`ReportGameEnd` 复用；结算模式化（六连珠 = 胜负记录 + 星尘公式，替换 TD 波次公式）
- [ ] 3-4 联机确定性验证：双端 StateHash 逐帧一致；对局 op-log 留档（复现工具 + 后续防作弊材料）
- [ ] 3-5 断线重连：落地服务器文档 A1 方案（重连恢复房间归属 + 当前帧续跑）；单局短可评估 op-log 重放
- [ ] 3-6 对战 UI：双方棋盘布局、垃圾子投放预警、胜负结算面板（复用 SettlePanel 模式）

**验收**：双端完整对局全程哈希一致；断线重连不崩不同步；人机/灰盒模式无回归。

***

## 阶段 4：微信小游戏平台接入

**目标**：微信真机跑通「分享进房 → 实时对战 → 结算 → 广告」全流程。**本阶段含全项目最大平台风险（4-1），建议提前至阶段 1 期间并行验证。**

- [ ] 4-1 网络传输适配（风险前置）：小游戏运行时无 UDP（LiteNetLib 不可用）→ NetMgr 传输层抽象 + WebSocket（wss）实现；GameServer 加 WS 端点（ASP.NET Core WebSocket）；FrameSyncMgr/RoomMgr 协议层不动；真机实测延迟/稳定性
- [ ] 4-2 微信登录：`wx.login` code → LoginServer `code2session` 端点（AppSecret/access_token 管理）→ openid 绑定账号；AccountMgr 适配静默登录
- [ ] 4-3 分享进房：`wx.shareAppMessage`（query 带房间号）→ 启动/前台 onShow 解析 query 自动加房；房间码输入兜底
- [ ] 4-4 广告封装 AdMgr：激励视频（开局护盾/结算星尘双倍，未看完不发奖）+ 插屏（仅结算后，日 ≤3）
- [ ] 4-5 平台复查：包体/首屏加载/真机性能（复用 VS 优化经验）、弱网对战与重连体验

**验收**：微信真机全流程闭环；两台真机 4G 对战可玩；广告展示与发奖正确。

## 阶段 5：流程闭环与留存

- [ ] 5-1 新手教学：3 步引导（落子 → 补成六连 → 看垃圾子砸对面），可跳过

**验收**：新用户无说明可独立完成首局；全流程无临时代码；连续 3 局无泄漏。

## 关键设计决策存档

| 决策 | 理由 |
| --- | --- |
| Puyo 式双棋盘 + 垃圾子对战 | 原作即此结构（各下各的、六连砸垃圾、堆满即输，用户澄清）；人机对战 = 完整对战的子集，AI 即对手，单机不是缩水版 |
| 实时帧同步（vs 回合制/异步挑战） | 保留原作"加速下落抢节奏"手感；帧同步基建已在塔防真机验证，成本最低 |
| 服务器纯转发（vs 服务端权威） | 框架现状即此架构，服务器无玩法逻辑成本最低；v1 好友对战无利益对抗，作弊风险可接受，段位期补影子重演 |
| 好友对战先行，匹配后置 | 冷启动空匹配池是小游戏 PvP 第一杀手；分享卡片自带对手 + 裂变；MatchMaker 基建已有，开启成本低 |
| 6 连默认，灰盒可降 5 | 原作为全合集最难游戏，六连达成率是留存生死线；调参优先于品牌，阶段 1 拍板 |
| AI = 确定性输入提供者 | 人机/联机/匹配机器人三场景共用一套代码 |
| 激励视频为主、插屏限频 | 对战体验优先；开局护盾是对战游戏最自然的广告点位 |

## 待定决策（开发中拍板）

- **6 连 vs 5 连 / 颜色数 / 棋盘尺寸**（阶段 1-9 拍板）
- **加速的协议形状**：独立 op vs 落子附带加速标志（阶段 1）
- **垃圾子颜色**：随机色（还原原作，可能意外帮对手）vs 无色障碍子（Puyo 式，需相邻消除解除）
- **对方棋盘表现**：完整镜像 vs 缩略信息版（竖屏空间取舍）
- **输入延迟手感**：BufferFrames=2（≈100ms）+ 下落动画时长是否够顺；本地预测后置
- **断线重连深度**：服务器 A1 基础方案 vs op-log 重放
- **星尘是否 v1 引入**（vs 纯胜负记录）：影响 Profile 表结构
- **服务器结算/校验的模式化范围**：TD 公式与坐标校验如何按模式分派
- **WS 传输方案细节**（4-1 验证后定）
