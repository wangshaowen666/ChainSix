# 客户端项目架构梳理（供 AI 快速了解项目）

> 用途：新对话/新协作者快速建立项目认知，按图索骥。基于代码现状整理，最后核对：2026-09-20。
> 配套文档：`服务器开发流程.md`（服务端 + 联机设计）、`吸血鬼幸存者玩法开发任务清单.md`（在研玩法）、`配置表Luban读写流程.md`（导表机制）。

## 一、项目概览

**形态**：Unity 单机/联机混合项目。热更架构：HybridCLR（代码热更）+ Addressables（资源热更）。

**双服务器架构**：

```
客户端 (Unity)
├── HttpMgr ───> LoginServer (ASP.NET Core Minimal API, .NET 8) ── 账号/JWT/养成数据（SQLite+Dapper）
└── NetMgr ────> GameServer (LiteNetLib UDP) ── 房间/匹配/帧同步/结算
```

**关键第三方**：HybridCLR、Addressables、Luban（配置表）、LiteNetLib（UDP）、Google.Protobuf（UDP/HTTP 统一协议，NuGet 3.35.1 netstandard2.0）、DOTween（UI 动画）、Odin Inspector（ToolBox 面板）、Input System 1.14（UI + 触摸）、Cinemachine（VS 战斗相机跟随）、Coffee.UIParticle、Joystick Pack（虚拟摇杆）。

**当前玩法状态**：
- **帧同步塔防（BattleTD/BattleLogic）**：已完成真机联调（联机基线玩法）。
- **吸血鬼幸存者（VampireSurvivor）**：在研主玩法。单机模式（`LocalDriver` 驱动）已完成阶段 1~3 主体：战斗骨架、核心循环（刷怪→击杀→掉宝石→升级三选一→变强）、6 武器范式、被动、敌种变体、精英、宝箱、HUD/选牌/结算面板；联机模式（阶段 5，`FrameSyncMgr` 驱动）未开始，复用塔防帧同步基建。
- 两个玩法共用同一套战斗骨架（BattleView/BattleMgr/驱动链/实体池/视图对账），联机时 VS 的 `VampireLogic` 零改动换驱动器。

## 三、启动与游戏流程

**完整链路**：

1. `Launch.unity`（Build Settings 唯一场景）-> `LaunchEntry`（CoreMgr.Init + 唯一 Update 泵）
2. `ProcedureLaunch`：创建 UICamera/UICanvas/UIRoot/EventSystem，加载 LoginPanel
3. `ProcedureVersionCheck` -> `ProcedureResCheckAA`（Addressables 热更：UpdateCatalog/CheckRes/Download）
4. `ProcedureLoadDll`：真机从 Addressables 加载 `Game.dll` 反射调 `GameLaunch.StartGame()`；Editor 直取程序集。AOT 补充元数据 dll 在 `Assets/Res/Dll/`
5. 热更流程：`GameMgr.Init` -> `ProcedurePreload`（加载 Luban 配置表 -> 直载 Main 场景）-> `ProcedureMain`（MainPanel）
6. 主界面开始 -> `GameEvent.ProcedureExitMain` -> `ProcedureChangeScene`（开 LoadingPanel -> 按"离开的场景类型"通知 GameMgr/CoreMgr.OnSceneExit -> LoadSceneAsync）-> `ProcedureBattle`
7. 联机路径：HTTP 登录（AccountMgr）-> `CoreMgr.Net.Connect`（自动 UDP token 认证）-> RoomMgr 建房/匹配 -> 服务器 `StartGamePush{start_frame, seed, player_ids}` -> `GameMgr.Battle.EnterBattle()` -> BattleTD
8. VS 单机路径：TTTT 临时入口"进入吸血鬼单机战斗" -> `BattleMgr.EnterBattle(BattleMode.VampireSurvivor)` -> `VampireView.Init`（自建 VampireLogic + LocalDriver）

**场景**：Build Settings 仅 `Launch.unity`；Addressables 场景（Remote_Scene 组）：`Main.unity`/`Battle.unity`/`Network.unity`/`Test.unity`。场景名常量在 `GameConfig.cs`。

**管理器生命周期**：`ManagerBase` 三虚方法 `OnInit()/OnSceneExit()/OnGameRestart()`，由 `GameMgr` 统一驱动（`s_managers` 数组静态注册）。**注册顺序**：DataTable → Account → PlayerData → NetMsg → HttpMsg → FrameSync → Room → UI → EntityPool → Battle → FrameAnim → FrameAnimGpu → Event。清理逆序执行（EntityPool 须在 Battle 前：战斗先 Dispose 归还实体，EntityPool 再清池）。**场景相关定制清理**：`ISceneAware` 接口（`OnSceneExit(SceneType)`），`GameMgr.OnSceneExit(sceneNm)` 倒序遍历下发；`SceneType` 定义在热更层 GameEnum 体系。Framework 层容器 `CoreMgr`（Procedure/Update/Timer/ClassPool/Event/Res/ObjectPool/Http/Net），业务层容器 `GameMgr`。**有跨场景状态的管理器必须注册进 GameMgr 的 s_managers 数组**。

## 四、核心框架

### 4.1 Update 驱动（全游戏唯一 Update 泵）

- `LaunchEntry.Update()` -> `CoreMgr.Update.MyUpdate(deltaTime, unscaledDeltaTime)`，业务禁止自建 MonoBehaviour Update
- `UpdateMgr` 管理有序 `IUpdateable` 列表：`int Priority`（大者先更新）+ `MyUpdate(dt, realDt)`；增删缓存下帧生效，无每帧 GC
- 现有优先级：NetMgr(100) -> FrameSyncMgr(90) -> FrameAnim(10) -> 业务实体/UI(0)（LocalDriver 注册为默认 0）
- **注意**：帧同步联机的逻辑层不走 UpdateMgr，由 FrameSyncMgr 消费缓冲帧后经 `OnFrame` 事件驱动（50ms 固定逻辑帧）
- VS 单机：`LocalDriver`（IUpdateable）注册 UpdateMgr，`realtimeSinceStartup` 墙钟累积每满 50ms 推一逻辑帧（帧号从 1 递增）直接调 `VampireLogic.Tick`；暂停=停步进不累积墙钟、不动 TimeScale；接口形状（OnFrame/OnRenderFrame）与 FrameSyncMgr 对齐，联机换驱动器零改动

### 4.2 UI 框架

- `UIPanelBase`（MonoBehaviour + `[RequireComponent(CanvasGroup)]`）：状态机 PanelState（None/Active/Hide/Cover/Recycle），生命周期 `OnInit(DUIPanel)/OnOpen(object userData)/OnHide/OnCover/OnResume/OnRecycle/OnClose`，DOTween 淡入淡出
- `UIMgr`：`PanelOn(DPnlId id, object userData = null)` / `PanelOff(DPnlId)` / `HasPanel(id)`；按 `TbUIPanel` 配置驱动（Name=Addressables 地址、Group=层级、AllowMult、HideCovered），ObjectPool 缓存面板，防重复打开与"加载中被关闭"
- `UIGroup`：每个层级组一个（挂 UIRoot 下按序排列），内部 LinkedList 面板栈：栈顶 Active、往下 Cover/Hide
- 现有面板（`DPnlId`，Gen/DPnlId.cs）：MainPanel=1 / SettingPanel=2 / BattlePanel=3 / LoadingPanel=4 / LevelUpPanel=5 / SettlePanel=6 / WeaponChoosePanel=7

### 4.3 资源加载（Addressables 封装）

- `ResMgr`（`CoreMgr.Res`）：`LoadSync<T>(key)` / `LoadAsync<T>(key, callback, userData)` / `LoadSceneAsync` / `Unload` / `PreloadWithLabel`；**key 即 Addressables 地址**
- 底层 `AddressableLoader` 自维护引用计数（并发同 key 复用 handle，计数归零才 Release）
- Addressables 分组（`Assets/AddressableAssetsData/AssetGroups/`）：Built In Data / Local / Remote_BattlePanel / Remote_Common / Remote_DataTable / Remote_Entity / Remote_GameDll / Remote_LoadingPanel / Remote_MainPanel / Remote_MetaDll / Remote_Scene / Remote_Setting

### 4.4 配置表（Luban）

- Excel 源：`DataTables/Datas/*.xlsx`（数据表 `#*.xlsx` + 注册 `__tables__.xlsx` + bean `__beans__.xlsx` + 枚举 `__enums__.xlsx`/`__pnlenums__.xlsx`），`DataTables/Defines/builtin.xml`（自定义类型 vector2/3/4），配置 `DataTables/luban.conf`（client/server/all 三 target，client topModule=cfg）
- 生成流程：`bash DataTables/gen.sh` 或 Unity ToolBox "导表"按钮（同一脚本，且唯一会自动补全 `DataTableMgr` 表属性的途径），导完产物三处同步：代码 -> `Game/DataTable/Gen/`（**生成物勿手改**）、二进制 -> `Assets/Res/LubanData/Bin/*.bytes`、可读 -> `Assets/Res/LubanData/Json/*.json`
- 读表：`GameMgr.DataTable.TbXXX.Get(id)`；AI 查表直接读 Json/Gen（见 `配置表Luban读写流程.md`，禁装临时工具）
- 当前表（11 张）：Effect / Entity / Plane / UIPanel / VSCharacter / VSEnemy / VSPassive / VSPickup / VSStage / VSWave / VSWeapon / VSWeaponLevel（+武器等级 TbVSWeaponLevel）
- Luban 生成的 bean 是纯 C# 类，可作为只读数据直接传入逻辑层；联机时服务器用 `-t all` 共享同一份定义

### 4.5 实体池与视图对账（EntityPool + ViewSync，表现层）

表现层收敛为两件套（`Game/Battle/View/`），TD/VS 共用：

- **`EntityPool`**（`GameMgr.EntityPool`，ManagerBase）：游戏实体（角色/怪物/子弹/特效）表现对象的"异步加载 + ObjectPool 池化"，资源 key 沿用 `#Entity.xlsx`。`Acquire(entityId, parent, callback)`：池命中同步回调、首次加载异步（回调时机不保证，调用方需容忍实体晚到）；`Release` 归还（隐藏并挂回池根）；闲置 10 秒自动销毁并卸载资源；`OnSceneExit` 清池。**实体对象只有表现**：逻辑全在逻辑层，禁止挂逻辑组件自我驱动
- **`ViewSync<TLogic,TView>`**：每逻辑帧 `Sync(logics)` 按逻辑层实体稳定 Id 对账——缺则建（spawn 回调返回 null = 异步加载中，登记 pending 不重复发起）/多则销/存在则刷新；`Attach(id, view)` 补挂晚到的异步实体；`Clear()` 战斗 Dispose 终态清理。内部容器复用，对账路径零 GC
- 接入范式见 VampireView：`Init` 末尾按实体类别构造 ViewSync（getId/spawn/refresh/despawn 四回调注入），`OnFrame` 里 `Logic.Tick` 后逐类 `Sync`

### 4.6 其他

- `TimerMgr`：`StartDelay/StartRepeat`（毫秒，返回 CancellationTokenSource）
- `EventMgr<TEventId>`：类级泛型事件管理器（`GameMgr.Event = EventMgr<GameEvent>`，`Register/Send` 自动推断回调参数类型）；事件枚举在 `GameEnum.cs`
- `ClassPool/ObjectPool`：类池/对象池（VS 逻辑实体池化走 `CoreMgr.ClassPool.Recycle`）
- `ParseUtil`（MiniJSON 封装）、`PlayerPrefsUtil`、`ShellUtil`（ToolBox 跑 shell 用）、`FileUtil`
- Profiler：`TimeProfiler`/`GCProfiler`（Development Build 用）

### 4.7 序列帧动画（`Game/Base/FrameAnim/`，CPU/GPU 双方案）

- **CPU 方案**：`FrameAnimAsset`（ScriptableObject，多 clip 配置）+ `FrameAnimPlayer`（纯 C# 池化播放器，时间累加器跨帧边界写 sprite）+ `FrameAnimMgr`（ManagerBase + IUpdateable，集中驱动 + 池化）+ `FrameAnimView`（MonoBehaviour 适配器，prefab 工作流）
- **GPU 方案**（`FrameAnimGpu*`）：`Graphics.DrawMeshInstanced` 批渲染序列帧的试验/基线套件（`FrameAnimGpuMgr/View/Util` + `FrameAnimGpuTest`），配套 `Res/Common/Shader/FrameAnimGpu*.shader`；与 `PerfBaselineTest` 共同构成阶段 7 渲染方案选型依据
- 全局 Pause/Resume（战斗暂停/选牌用）；回收延迟一帧移除并归还池

## 五、战斗与帧同步架构（重点）

**模式**：Lockstep 变体（操作转发 + 双端确定性执行）。逻辑层/表现层严格分离。两套玩法共用骨架，差异只在 Logic/View 对与驱动器来源。

### 5.0 通用骨架

```
联机：NetMgr(UDP 收包, Priority=100) -> NetMsgHandler（protobuf 解析 FrameData）
      -> FrameSyncMgr(Priority=90, IUpdateable：墙钟累积每 50ms 消费一帧缓冲)
      -> OnFrame 事件 -> XxxView -> XxxLogic.Tick(absFrame, inputs)
单机：LocalDriver(IUpdateable, Priority=0) -> 墙钟累积 50ms -> OnFrame/OnRenderFrame -> VampireView
操作上行：GameMgr.FrameSync.SendInput(opType, p1, p2)（LiteNetLib ReliableOrdered）
```

- FrameSyncMgr 缓冲策略：`BufferFrames=2`（不足暂停防抖动）、`MaxBufferFrames=6`、`CatchupFrames=2`（积压时每周期额外消费 2 帧追赶）
- 逻辑帧 **50ms（20 帧/秒）**，客户端常量须与服务器一致；表现层经插值补足渲染帧率
- 胜负：逻辑层判定 GameOver -> `RoomMgr.ReportGameEnd(frameId)` 上报服务器广播结算（联机）

### 5.1 塔防 `TowerDefence/`（联机基线玩法，已完结）

- `BattleLogic(seed, playerIds)` 构造（种子与参战玩家由服务器 StartGamePush 下发）；`Tick(absFrame, inputs)` 内部固定序：应用操作 -> 按帧号刷怪 -> 塔攻击（列表序）-> 敌人移动（倒序）-> RemoveAll 清尸 -> 失败判定
- 数据结构全为有序 List（LogicEnemy/LogicTower/LogicPlayer）；`StateHash()`（FNV-1a 64）供双端逐帧校验；`LastReject` 记录被拒操作
- 操作：OpType 1=放塔(param=x,y)、2=升级塔；数值常量硬编码类顶部（服务器侧有副本需同步改）
- `BattleTD` 表现层：Init 取 Room 的 StartFrame/Seed/BattlePlayerIds -> new BattleLogic -> 相机 -> 运行时图元视图（URP 材质工厂 `ViewMats.GetMat` 兜底链）-> 订阅 FrameSyncMgr.OnFrame
- **已知副本**：BattleTD 里有一份 `BattlePath()` 路径点硬编码与 BattleLogic 重复，改路径两处都要动

### 5.2 吸血鬼幸存者 `VampireSurvivor/`（在研主玩法）

#### 逻辑层 `Logic/`（纯 C#，零 UnityEngine 依赖，Tick 零 GC）

**`VampireLogic`**（主编排，290 行）：
- 构造 `VampireLogic(long seed)`：读表（TbVSCharacter 玩家半径 / TbVSStage 场地半宽高）→ 装配六系统（构造期读各自表，Tick 零分配）→ 创建 P1 英雄（满血出生，**初始武器延迟装备**：`PendingStartWeapon=true` → 表现层弹 WeaponChoosePanel → `EquipStartWeapon(weaponId)` 装备并恢复驱动）
- `Tick(absFrame, inputs)` **十步固定编排（步骤顺序即确定性本身）**：
  1. 应用输入移动（含场地边界夹取 + 更新朝向）→ 2. Regen 回复 → 3. 武器开火（英雄序→武器序固定遍历 `weapon.Tick`）→ 4. `SysWave.Tick`（波次刷怪）→ 5. `SysEnemy.TickMove`（追击最近存活玩家）→ 6. `SysEnemy.TickSuicide`（接触自爆，玩家不扣血）→ 7. `SysProjectile.Tick`（弹幕飞行/命中）→ 7.5 `SysField.Tick`（持续区域）→ 8. `SysDrop.Tick`（磁吸/拾取）→ 9. 集中清扫（敌人/弹幕/区域回池，倒序 RemoveAt）→ 10. 失败判定（全灭 GameOver）
- 公共状态：四类实体有序 List（Heroes/Enemies/Projectiles/Drops）+ 三类帧事件 List（HitEvents/LevelUpEvents/ChestEvents，Tick 开头清上帧）+ `AllocId()` 稳定自增 ID + `XRng` 确定性随机源 + `AddKill()` 击杀入账
- `StateHash()`：FNV-1a 64，先 Mix 自身状态（帧号/GameOver/英雄字段），再按固定序调各系统 `HashState(ref h)`；**新增哈希字段只允许追加到各系统 HashState 尾部，禁止重排**
- `Dispose()`：全实体回池（`CoreMgr.ClassPool.Recycle`）

**`Systems/` 六系统**（构造注入 Logic 引用，交互全显式调用，无 Dictionary/foreach，零 GC）：

| 系统 | 职责 |
| --- | --- |
| `VsWaveSystem` | 分钟段时间轴刷怪：每行=自 StartMinute 起每 IntervalFrames 刷 PerWave 只的流，同段可多行混刷；强度=波次表系数 × 敌表基础值 |
| `VsEnemySystem` | 敌人移动（行为分发：追击/直线横穿 Linear）+ 接触自爆判定；直线怪越出场地边界回收（不计击杀不掉落） |
| `VsProjectileSystem` | 弹幕飞行/圆形命中/穿透计数/超时回收；命中 → `VsHitEvent` + 扣血 + 击退（冲量逐帧衰减）+ `AddKill`；公开 `HitDirect` 供区域系统复用结算语义 |
| `VsFieldSystem` | 持续区域两范式：Orbit 环绕体（Amount 单元均分圆周公转，旋转矩阵增量免三角函数）/ Aura 光环（常驻圈周期灼烧）；区域命中复用弹幕结算 |
| `VsDropSystem` | 击杀掉落：普通怪→经验宝石、精英→宝箱（`LogicDrop.PickupId` 分发）；磁吸（吸引速度>玩家移速）与拾取（英雄碰撞半径）；宝石走 GainXp、宝箱走 OpenChest |
| `VsLevelUpSystem` | 经验入账（×Growth）→ 升级（曲线=TbVSStage 线性 ExpBase+ExpStep×(n-1)，可连升）→ 每级 `VsLevelUpEvent` 入队逐组三选一（ChoiceCount=3）；`CurrentChoices` 选牌池（未持有 + 未满级，XRng 无放回抽 3）；`ApplyChoice` 应用武器/被动；`OpenChest` 宝箱随机升级/保底治疗（池空回血） |

**`EntityLogic/` 七类实体**（池化对象，Reset 复位）：
- `LogicHero`：位置/朝向/HP/等级经验/Weapons 列表 + `Stats`（属性系统）
- `LogicPlayerStats`：13 项属性（`VSAttrType` 1~13 为数组下标，统一 Fix）；基础值=角色表，被动修改器叠加（`LogicPassive` 槽），结算写回宿主 MaxHp/MoveSpeed/MagnetRadius，其余 `Get()` 供消费；`ApplyRegen` 每帧入账
- `LogicWeapon`：**范式(behavior)×目标策略(targetStrategy) 表驱动**——Projectile（直线散射/抛物线变体）、Instant（弧形横扫，本地去重）、Area（Orbit/Aura 转发 SysField）；目标策略 Nearest/Random/Facing/MoveDir；数值=TbVSWeaponLevel（id=武器id*100+等级）× 属性加成（Might/Cooldown/Amount/Area/ProjSpeed）；`LevelUp()` 刷新等级行
- `LogicEnemy`：追击/直线行为、敌种 CfgId/Exp（进 Hash）、精英 IsElite/受击 LastHitFrame
- `LogicProjectile` / `LogicField` / `LogicDrop`：弹道/区域/掉落物（PickupId 表驱动分发）

**`VsEvents.cs` 跨层结构体**：`VsInput`（PlayerIndex+Fix 方向）、`VsHitEvent`、`VsLevelUpEvent`、`VsLevelUpChoice`、`VsChestEvent`、`VsHash.Mix`（FNV-1a 混合工具）。**逻辑层不产字符串**，文案由表现层查表组装。

#### 表现层 `View/`

- **`VampireView`**（partial ×3，只做组装与帧回调编排）：
  - `Init`：EntityRoot（旋转 90°X）→ EnemyHpBarRenderer → `new VampireLogic(seed)` + `LocalDriver` + VsHudPresenter + VsFollowCamera → **表现实体 id 反查链**（角色表→实体、关卡表→飘字实体、角色初始武器→弹体/命中特效实体；逻辑实体不携带表现字段）→ 五个 ViewSync（Hero/Enemy/Bolt/Drop/Field）→ 订阅 OnFrame/OnRenderFrame
  - `VampireView.Entities.cs`：五类实体对账三件套（spawn 走 EntityPool.Acquire 异步容错）
  - `VampireView.Fx.cs`：一次性表现（伤害飘字 DamageTextView 池化、命中特效、死亡冒血、宝箱公告）
- **`VsHudPresenter`**：HUD 刷新（BattlePanel 的 VS 部分，逐帧拉取直至面板就绪）+ 升级选牌流程（暂停驱动 → 弹 LevelUpPanel → `VsLevelUpChosen` 事件回推 → 连升换题 `VsLevelUpChoicesChanged`）+ 开局武器选择（WeaponChoosePanel，`VsStartWeaponChosen`）+ 死亡结算（SettlePanel，统计快照走 userData）
- **`VsFollowCamera`**：Cinemachine 虚拟相机跟随英雄
- **`EnemyHpBarRenderer`**：全场景敌人血条合并为**单个动态 Mesh**（每敌背景+前景 quad），顶点数组复用 + `Mesh.Clear(keepVertexLayout)` 零 GC，避开 SpriteRenderer 合批问题
- **插值**：`OnRenderFrame(alpha)` 驱动位置双缓冲插值（逻辑帧率与渲染帧率解耦，首帧/池化复用不跳跃）

#### 驱动与输入

- `LocalDriver`：墙钟累积固定步长（详见 4.1）；`RegisterInput(IBattleInput)` 帧边界采样产出 `VsInput` 列表；`Pause/Resume`（暂停不追帧）
- `IBattleInput`（输出 Fix 归一化方向）/ `JoystickInput`（包装 GameJoystick）；逻辑层禁止读 `Input.*`
- 摇杆获取解耦：BattlePanel 登记到 `GameMgr.Battle` → `GameEvent.VsJoystickReady` 广播 → VampireView 查缓存 + 订阅就绪事件

### 5.3 FixMath（`Game/Battle/FixMath.cs`，全局类型无命名空间）

- `Fix`（readonly struct，Q16.16，long Raw）：`FromInt/FromDouble(仅常量初始化)/FromRaw`、`Int/AsFloat(仅表现层)`、`Sqrt`（整数位扫描，确定性）、运算符重载、`Zero/Half/One`
- `XRng`（xorshift64*）：`new XRng(seed)`（0 自动换黄金分割常数）、`NextInt(min,max)`、`NextFix(min,max)`、`Chance(pct)`、`ChanceBp(万分比)`

### 5.4 确定性纪律（逻辑层禁用，TD/VS 共同遵守）

| 禁用 | 替代 |
| --- | --- |
| float / double | Fix；常量 `Fix.FromDouble(x)` 仅限初始化 |
| UnityEngine.Random / System.Random | XRng + 同步种子（联机种子服务器下发） |
| Time.deltaTime / Time.time | 固定逻辑帧计数 |
| Dictionary 遍历 | 有序 List |
| Physics | 自研圆形碰撞（Fix 距离平方比较） |
| Tick 内 new / 装箱 / LINQ / foreach 闭包 | 池化（CoreMgr.ClassPool）、预分配、for 循环 |

## 六、网络层

- `NetMgr`（Framework，LiteNetLib UDP）：连接/心跳/原始字节收发，Priority=100；UDP 连接后自动 token 认证（UdpLoginReq，失败 3 次断开；认证时同步清理踢旧连接）
- `HttpMgr`（Framework）：UnityWebRequest 字节级收发，Content-Type: application/x-protobuf
- `NetMsgHandler`（热更）：protobuf 协议封装/解析/分发（注册式）；`RoomMgr`：建房/加房/匹配/就绪/StartGamePush/ReportGameEnd，暴露 CurRoomId/StartFrame/Seed/BattlePlayerIds；`HttpMsgHandler` + `ApiRegistry`（HTTP 接口注册表，由 NetApi.cs 注释驱动自动补全）
- `AccountMgr`：HTTP 注册/登录/token（PlayerPrefs 持久化）；`PlayerDataMgr`：GET /data 养成数据（只读防作弊）
- **proto 唯一协议源**：`Server/wgame-server/Proto/*.proto`（net_common/net_auth/net_room/net_battle/net_profile/net_push + NetApi.cs）；改后跑 `DataTables/gen_proto.sh` 或 ToolBox "导 Proto" 生成客户端代码；命名约定 `XxxReq/XxxResp/XxxPush`，ErrorCode 固定 field 1；UDP 与 HTTP 统一 protobuf 信封 NetMsgEnvelope
- 服务器构建：`dotnet build Server/wgame-server/wgame-server.sln`（还原 Grpc.Tools 2.83.0 → protoc 35.1；客户端 protobuf 运行时 dll 为 NuGet google.protobuf 3.35.1 netstandard2.0，与 protoc 同版本配套）
- **小游戏平台注意**：LiteNetLib 为原生 UDP，微信/抖音/TapTap 小游戏运行时不可用；ChainSix 工程已抽象 `ITransport`（WebSocket 方案），本工程迁移指引见 ChainSix 仓库《ChainSix工程迁移清单.md》

## 九、已知坑与历史遗留

- **ProcedureBattle.EnterBattle() 被注释**，战斗实际由 `TTTT.cs`（测试 IMGUI）触发；TTTT/LoginTest 是测试代码，生产流程接入时要归位
- **BattleTD 里有一份 BattlePath() 路径点硬编码副本**（与 BattleLogic 重复），改路径两处都要动
- **URP 材质真机粉色**：shader 只进 bundle 时 `Shader.Find` 返回 null，材质兜底链：URP Lit -> 克隆管线 defaultMaterial -> Sprites/Default；URP 颜色属性是 `_BaseColor`（已封装进 ViewMats）
- **BoxCollider 被裁**：HybridCLR link.xml 扫不到按类名添加的组件，独立 `Assets/link.xml` preserve `UnityEngine.PhysicsModule`（另有 ProfilerCategory/ProfilerRecorder/Graphics 手动保留项）
- **热更脚本挂载规则**：热更脚本只能挂 Addressables/AB 场景与预制体，Build Settings 主包场景（Launch.unity）绝不能挂
- **IL2CPP AOT**：protobuf 需 link.xml；AOT 补充元数据 dll 在 `Assets/Res/Dll/`（GameLaunch.ReplenishMeta 处理）
- **Google.Protobuf.dll 来源**：NuGet `google.protobuf 3.35.1` 的 `lib/netstandard2.0/`（与 protoc 35.1 配套）；不要拿 `Tools/Luban/` 下 Luban 自带的 dll 用（引用 System.Runtime.CompilerServices.Unsafe，Unity 校验不过）
- **VS Tick 顺序纪律**：VampireLogic.Tick 十步顺序与 StateHash 混合顺序即确定性，调整任意两步顺序都会改变演算结果；拆分重构时"步骤顺序与混合顺序逐字不变"
- **VS prefab 待建项**：以吸血鬼任务清单内标注为准（缺 prefab 时功能降级/报错，不影响其他系统）

## 十、开发纪律汇总（必须遵守）

1. 日志统一用框架 `Log` 类（`Log.Info/Warning/Error`），**禁止** `UnityEngine.Debug.Log*`
2. 逻辑层确定性纪律见 5.4 表格；表现层读逻辑层数据只允许 `Fix.AsFloat`

6. proto 唯一协议源在服务器目录 `Server/wgame-server/Proto/`，字段号上线后只能追加
7. 资源 key 即 Addressables 地址；加载/卸载必须走 `CoreMgr.Res`（有引用计数），禁止直接调 Addressables API
8. 编辑 xlsx 用本机 python3 + openpyxl；改完表执行 `bash DataTables/gen.sh`（详见 `配置表Luban读写流程.md`）
