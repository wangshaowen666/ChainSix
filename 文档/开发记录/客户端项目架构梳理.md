# 客户端项目架构梳理（供 AI 快速了解项目）

> 用途：新对话/新协作者快速建立项目认知，按图索骥。基于代码现状整理，最后核对：2026-08-25。
> 配套文档：`服务器开发流程.md`（服务端 + 联机设计）、`吸血鬼幸存者玩法开发任务清单.md`（在研玩法）。

## 一、项目概览

**形态**：Unity 单机/联机混合项目。热更架构：HybridCLR（代码热更）+ Addressables（资源热更）。

**双服务器架构**：

```
客户端 (Unity)
├── HttpMgr ───> LoginServer (ASP.NET Core Minimal API, .NET 8) ── 账号/JWT/养成数据（SQLite+Dapper）
└── NetMgr ────> GameServer (LiteNetLib UDP) ── 房间/匹配/帧同步/结算
```

**关键第三方**：HybridCLR、Addressables、Luban（配置表）、LiteNetLib（UDP）、Google.Protobuf（UDP/HTTP 统一协议）、DOTween（UI 动画）、Input System 1.14（UI + 触摸）、Cinemachine（相机跟随，插件方式装于 `Assets/Plugins/Cinemachine`，asmdef 名 `Cinemachine`）。

**当前玩法状态**：帧同步塔防（BattleTD/BattleLogic）已完成真机联调；旧单机 Survival 及其 Entity 体系已删除（表现层收敛为 EntityPool + ViewSync，见 4.5）；吸血鬼幸存者玩法在研——**两种模式**：单机模式（单人·多关卡闯关，`LocalDriver` 驱动，先落地）+ 联机模式（双人·无尽，`FrameSyncMgr` 驱动，后置，复用塔防帧同步基建），同一 `VampireLogic` 双驱动零改动（见任务清单）。

## 三、启动与游戏流程

**完整链路**：

1. `Launch.unity`（Build Settings 唯一场景）-> `LaunchEntry`（CoreMgr.Init + 唯一 Update 泵）
2. `ProcedureLaunch`：创建 UICamera/UICanvas/UIRoot/EventSystem，加载 LoginPanel
3. `ProcedureVersionCheck` -> `ProcedureResCheckAA`（Addressables 热更：UpdateCatalog/CheckRes/Download）
4. `ProcedureLoadDll`：真机从 Addressables 加载 `Game.dll` 反射调 `GameLaunch.StartGame()`；Editor 直取程序集。AOT 补充元数据 dll 在 `Assets/Res/Dll/`
5. 热更流程：`GameMgr.Init` -> `ProcedurePreload`（加载 Luban 配置表 -> 直载 Main 场景）-> `ProcedureMain`（MainPanel）
6. 主界面开始 -> `GameEvent.ProcedureExitMain` -> `ProcedureChangeScene`（开 LoadingPanel -> 按"离开的场景类型"通知 GameMgr/CoreMgr.OnSceneExit -> LoadSceneAsync）-> `ProcedureBattle`
7. 联机路径：HTTP 登录（AccountMgr）-> `CoreMgr.Net.Connect`（自动 UDP token 认证）-> RoomMgr 建房/匹配 -> 服务器 `StartGamePush{start_frame, seed, player_ids}` -> `GameMgr.Battle.EnterBattle()` -> BattleTD

**场景**：Build Settings 仅 `Launch.unity`；Addressables 场景（Remote_Scene 组）：`Main.unity`/`Battle.unity`/`Network.unity`/`Test.unity`。场景名常量在 `GameConfig.cs`。

**管理器生命周期**：`ManagerBase` 三虚方法 `OnInit()/OnSceneExit()/OnGameRestart()`，由 `ManagerContainerHelper` 统一驱动（场景退出为场景无关的通用清理，不携带场景信息）。**场景相关定制清理**：热更层 `ISceneAware` 接口（`OnSceneExit(SceneType)`），`GameMgr.OnSceneExit(SceneType)` 倒序遍历时先做通用清理、再对实现 `ISceneAware` 的管理器下发"离开的场景类型"。`SceneType` 枚举定义在**热更层**（GameEnum.cs，新增场景类型只需热更）。`ProcedureChangeScene` 从 `_fsm.GetData(ProcedureKey.CurSceneType)` 取当前场景类型调 `GameMgr.OnSceneExit(SceneType)` / `CoreMgr.OnSceneExit()`（框架层无场景信息），加载完成后 `SetData` 推进为目标类型（启动时由 `ProcedurePreload` 初始化）。Framework 层容器 `CoreMgr`（Procedure/Update/Timer/ClassPool/Event/Res/ObjectPool/Http/Net），业务层容器 `GameMgr`（DataTable/Account/PlayerData/NetMsg/HttpMsg/FrameSync/Room/UI/EntityPool/Battle/FrameAnim）。**有跨场景状态的管理器必须注册进 GameMgr 的 s_managers 数组**，否则收不到清理回调；**注册顺序影响逆序清理顺序**（EntityPool 须排在 Battle 前：战斗先 Dispose 归还实体，EntityPool 再清池）。

## 四、核心框架

### 4.1 Update 驱动（全游戏唯一 Update 泵）

- `LaunchEntry.Update()` -> `CoreMgr.Update.MyUpdate(deltaTime, unscaledDeltaTime)`，业务禁止自建 MonoBehaviour Update
- `UpdateMgr` 管理有序 `IUpdateable` 列表：`int Priority`（大者先更新）+ `MyUpdate(dt, realDt)`；增删缓存下帧生效，无每帧 GC
- 现有优先级：NetMgr(100) -> FrameSyncMgr(90) -> 业务实体/UI(0)
- **注意**：帧同步战斗的逻辑层不走 UpdateMgr，由 FrameSyncMgr 消费缓冲帧后经 `OnFrame` 事件驱动（50ms 固定逻辑帧）
- 吸血鬼单机：`LocalDriver`（IUpdateable，Priority 默认 0）注册 UpdateMgr，`realtimeSinceStartup` 墙钟累积每满 33ms 推一逻辑帧（帧号从 1 递增）直接调 `VampireLogic.Tick`；暂停=停步进不累积墙钟、不动 TimeScale（阶段 2-8 选牌/5-4 暂停菜单用）；接口形状对齐 `FrameSyncMgr.OnFrame`，阶段 7 联机换 FrameSyncMgr 驱动 Logic/表现层零改动

### 4.2 UI 框架

- `UIPanelBase`（MonoBehaviour + `[RequireComponent(CanvasGroup)]`）：状态机 PanelState（None/Active/Hide/Cover/Recycle），生命周期 `OnInit(DUIPanel)/OnOpen(object userData)/OnHide/OnCover/OnResume/OnRecycle/OnClose`，DOTween 淡入淡出
- `UIMgr`：`PanelOn(DPnlId id, object userData = null)` / `PanelOff(DPnlId)` / `HasPanel(id)`；按 `TbUIPanel` 配置驱动（Name=Addressables 地址、Group=层级、AllowMult、HideCovered），ObjectPool 缓存面板，防重复打开与"加载中被关闭"
- `UIGroup`：每个层级组一个（挂 UIRoot 下按序排列），内部 LinkedList 面板栈：栈顶 Active、往下 Cover/Hide
- 现有面板：MainPanel=1 / SettingPanel=2 / BattlePanel=3 / LoadingPanel=4（枚举 `DPnlId` 由表生成）

### 4.3 资源加载（Addressables 封装）

- `ResMgr`（`CoreMgr.Res`）：`LoadSync<T>(key)` / `LoadAsync<T>(key, callback, userData)` / `LoadSceneAsync` / `Unload` / `PreloadWithLabel`；**key 即 Addressables 地址**
- 底层 `AddressableLoader` 自维护引用计数（并发同 key 复用 handle，计数归零才 Release）
- Addressables 分组（`Assets/AddressableAssetsData/AssetGroups/`）：Remote_BattlePanel / Remote_Common / Remote_DataTable / Remote_Entity / Remote_GameDll / Remote_MetaDll / Remote_Scene / Local 等

### 4.4 配置表（Luban）

- Excel 源：`DataTables/Datas/*.xlsx`（`#UIPanel.xlsx`/`#Entity.xlsx`/`#Plane.xlsx`/`#Effect.xlsx` + `__tables__` 等），配置 `DataTables/luban.conf`（client/server/all 三 target，client topModule=cfg）
- 生成流程：`DataTables/gen.sh` 或 Unity ToolBox "ImportExcel" 按钮（`Game/Editor/ToolBox.Excel.cs`，导完自动补全 `DataTableMgr` 表属性并刷新）
- 产物：代码 -> `Game/DataTable/Gen/`（`Tables.cs`/`Tb*.cs`/`D*.cs`，**生成物勿手改**）；数据 -> `Assets/Res/LubanData/Bin/*.bytes`（客户端用）
- 读表：`DataTableMgr.LoadTable()`（ProcedurePreload 调用）构造 `cfg.Tables`；访问如 `GameMgr.DataTable.TbEntity[eId].Name`；表 API：`Get/GetOrDefault/this[]/DataMap/DataList`
- Luban 生成的 bean 是纯 C# 类，可作为只读数据直接传入逻辑层；联机时服务器用 `-t all` 共享同一份定义

### 4.5 实体池与视图对账（EntityPool + ViewSync，表现层）

旧 Entity 体系（EntityMgr/EntityBase/PlayerPlane/EnemyPlane/BulletEntity/EffectEntity/EntityStats，逻辑寄生在 MonoBehaviour 上）已随废弃 Survival 一起删除，表现层收敛为两件套（`Game/Battle/View/`）：

- **`EntityPool`**（`GameMgr.EntityPool`，ManagerBase）：游戏实体（角色/怪物/子弹/特效）表现对象的"异步加载 + ObjectPool 池化"，资源 key 沿用 `#Entity.xlsx`。`Acquire(entityId 或 key, parent, callback)`：池命中同步回调、首次加载异步（回调时机不保证，调用方需容忍实体晚到）；`Release` 归还（隐藏并挂回池根）；闲置 10 秒自动销毁并卸载资源；`OnSceneExit` 清池（注册顺序在 BattleMgr 前，保证战斗先 Dispose 归还实体）。**实体对象只有表现**：逻辑全在逻辑层，禁止挂逻辑组件自我驱动
- **`ViewSync<TLogic,TView>`**（通用视图对账器，TD/VS 共用）：每逻辑帧 `Sync(logics)` 按逻辑层实体稳定 Id 对账--缺则建（spawn 回调返回 null = 异步加载中，登记 pending 不重复发起）/多则销/存在则刷新；`Attach(id, view)` 补挂晚到的异步实体（实体已死或已 Clear 则直接回收）；`Clear()` 战斗 Dispose 终态清理。内部容器复用，对账路径零 GC
- **接入范式见 BattleTD**：`InitViews` 末尾按实体类别构造 ViewSync（getId/spawn/refresh/despawn 四回调注入），`OnFrame` 里 `Logic.Tick` 后调 `SyncViews()`；VS 等新玩法直接复用，不会再出现第三套实体体系

### 4.6 其他

- `TimerMgr`：`StartDelay/StartRepeat`（毫秒，返回 CancellationTokenSource）
- `EventMgr<TEventId>`：类级泛型事件管理器（事件 ID 类型提升为泛型参数，业务用 `GameMgr.Event = EventMgr<GameEvent>`，`Register/Send` 只需推断回调参数类型，无 `<GameEvent, T>` 双泛型噪音）；事件枚举在 `GameEnum.cs` 的 `GameEvent`
- `ClassPool/ObjectPool`：类池/对象池

### 4.7 序列帧动画（`Game/Base/FrameAnim/`）

- `FrameAnimAsset`（ScriptableObject，Create 菜单 Game/FrameAnimAsset）：多动画配置，每条 = `{clipName, List<Sprite>, duration 总时长, loop}`；帧间隔 = 总时长/帧数/速度。同资源 Sprite 建议同图集（换帧不破坏 SpriteRenderer 合批）
- `FrameAnimPlayer`（纯 C#，池化）：核心 = 时间累加器，跨帧边界才写 `SpriteRenderer.sprite`；支持 Play/Stop/SetSpeed/Pause/Resume/onFinish 回调；时间尖峰连续跨帧直达正确帧
- `FrameAnimMgr`（ManagerBase + IUpdateable，Priority=10，注册于 GameMgr.FrameAnim）：集中驱动所有播放器 + 播放器走项目统一对象池（`CoreMgr.ClassPool`，FrameAnimPlayer 实现 IResetable）；全局 Pause/Resume（战斗暂停/选牌用）；回收延迟一帧移除并归还池，onFinish 回调内可安全 Release
- `FrameAnimView`（MonoBehaviour 适配器，prefab 工作流）：挂带 SpriteRenderer 的节点，OnEnable 建播放器/OnDisable 归还，适配对象池；战斗代码驱动路径直接用 CreatePlayer 不必挂此组件
- 参考：`Assets/Scripts/Temp/PAnimFrame/` 为旧项目搬来的参考件（依赖缺失 + `#if UITOOL_OPEN` 空壳，不可直接用）

## 五、战斗与帧同步架构（重点）

**模式**：Lockstep 变体（操作转发 + 双端确定性执行）。逻辑层/表现层严格分离。

### 逻辑层 `Battle/TD/BattleLogic.cs`（纯 C#，零 UnityEngine 依赖）

- 构造 `BattleLogic(long seed, int[] playerIds)`（种子与参战玩家由服务器 StartGamePush 统一下发）
- `Tick(int absFrame, IList<PlayerInput> inputs)`：以服务器绝对帧号锚定；内部固定序：应用操作 -> 按帧号刷怪 -> 塔攻击（列表序）-> 敌人移动（倒序）-> RemoveAll 清尸 -> 失败判定
- 数据结构全为有序 List（LogicEnemy/LogicTower/LogicPlayer）；`StateHash()`（FNV-1a 64）供双端逐帧校验；`LastReject` 记录被拒操作
- 操作：OpType 1=放塔(param=x,y)、2=升级塔；数值常量硬编码类顶部（待配置化，服务器侧有副本需同步改）

### 表现层 `Battle/TD/TdView.cs`（继承 BattleView）

- `Init()`：取 Room 的 StartFrame/Seed/BattlePlayerIds -> new BattleLogic -> 相机初始化（优先复用场景 BattleCamera，否则自建俯视相机）-> 运行时图元视图（Plane/Cube/Cylinder，URP 材质工厂 `GetMat` 含真机 shader 兜底链：URP Lit -> 管线 defaultMaterial -> Sprites/Default）-> 订阅 `FrameSyncMgr.OnFrame`
- `OnFrame(frame)`：丢弃 < StartFrame 的帧 -> `_logic.Tick(...)` -> `SyncViews()`（两个 ViewSync 对账器：缺则建/多则销/坐标刷新 `en.X.AsFloat`）
- GameOver：`RoomMgr.ReportGameEnd(frameId)` 上报服务器广播结算

### 驱动链路

```
NetMgr(UDP 收包, Priority=100)
  -> NetMsgHandler（protobuf 解析 FrameData，事件抛出）
  -> FrameSyncMgr(Priority=90, IUpdateable：墙钟累积每 50ms 消费一帧缓冲)
  -> OnFrame 事件 -> BattleTD -> Logic.Tick
操作上行：GameMgr.FrameSync.SendInput(opType, p1, p2)（LiteNetLib ReliableOrdered）
```

- FrameSyncMgr 缓冲策略：`BufferFrames=2`（不足暂停防抖动）、`MaxBufferFrames=6`、`CatchupFrames=2`（积压时每周期额外消费 2 帧追赶）
- 逻辑帧 50ms（20 帧/秒），客户端常量须与服务器一致

### 战斗入口 `BattleMgr`

- `EnterBattle()`：塔防路径前置校验 `GameMgr.Room.StartFrame != 0`（收到 StartGamePush）；`EnterBattle(BattleMode)` 按模式分支（`BattleView.cs` 枚举：TowerDefense / VampireSurvivor）
- `PendingMode`：预置的战斗模式（进入战斗场景前的临时入口设置，`ProcedureBattle` 读取后传入 `EnterBattle(mode)`）
- `OnSceneExit(SceneType.Battle/Network)/OnGameRestart` 自动 Dispose 战斗
- **现状**：塔防由 `TTTT.cs` 订阅 `Room.OnStartGamePush` 触发（联机测试代码）；吸血鬼单机模式（阶段 1~4，`LocalDriver` 驱动）临时入口 TTTT"7.进入吸血鬼单机战斗"，联机模式（阶段 5，`FrameSyncMgr` 驱动）复用塔防联机路径

### FixMath（`Game/Battle/FixMath.cs`，全局类型无命名空间）

- `Fix`（readonly struct，Q16.16，long Raw）：`FromInt/FromDouble(仅常量初始化)/FromRaw`、`Int/AsFloat(仅表现层)`、`Sqrt`（整数位扫描，确定性）、运算符重载、`Zero/Half/One`
- `XRng`（xorshift64*）：`new XRng(seed)`（0 自动换黄金分割常数）、`NextInt(min,max)`、`NextFix(min,max)`（字面量）、`Chance(pct)`、`ChanceBp(万分比)`

### 确定性纪律（逻辑层禁用）

| 禁用 | 替代 |
| --- | --- |
| float / double | Fix；常量 `Fix.FromDouble(x)` 仅限初始化 |
| UnityEngine.Random / System.Random | XRng + 同步种子 |
| Time.deltaTime / Time.time | 固定逻辑帧计数 |
| Dictionary 遍历 | 有序 List |
| Physics | 自研碰撞或不用 |

## 六、网络层

- `NetMgr`（Framework，LiteNetLib UDP）：连接/心跳/原始字节收发，Priority=100；UDP 连接后自动 token 认证（UdpLoginReq，失败 3 次断开；认证时同步清理踢旧连接）
- `HttpMgr`（Framework）：UnityWebRequest 字节级收发，Content-Type: application/x-protobuf
- `NetMsgHandler`（热更）：protobuf 协议封装/解析/分发（注册式）；`RoomMgr`：建房/加房/匹配/就绪/StartGamePush/ReportGameEnd，暴露 CurRoomId/StartFrame/Seed/BattlePlayerIds
- `AccountMgr`：HTTP 注册/登录/token（PlayerPrefs 持久化）；`PlayerDataMgr`：GET /data 养成数据（Gold/StageProgress/TowerLevels，只读防作弊）
- **proto 唯一协议源**：`Server/wgame-server/Proto/*.proto`；改后跑 `DataTables/gen_proto.sh` 或 ToolBox "导 Proto" 生成客户端代码；命名约定 `XxxReq/XxxResp/XxxPush`，ErrorCode 固定 field 1；`NetApi.cs` 手写 HTTP URL 常量
- UDP 与 HTTP 统一 protobuf；信封 NetMsgEnvelope

## 十、开发纪律汇总（必须遵守）

1. 日志统一用框架 `Log` 类（`Log.Info/Warning/Error`），**禁止** `UnityEngine.Debug.Log*`
2. 逻辑层确定性纪律见第五节表格；表现层读逻辑层数据只允许 `Fix.AsFloat`
3. 业务代码写在 `Assets/Scripts/Game`（热更程序集）；Framework/Launch 是 AOT 主包，改动需重出包
4. Update 统一走 `CoreMgr.Update` 注册，禁止业务 MonoBehaviour 自建 Update
5. 生成物勿手改：`Game/DataTable/Gen/`、`Game/Net/Proto/`
6. proto 唯一协议源在服务器目录 `Server/wgame-server/Proto/`，字段号上线后只能追加
7. 资源 key 即 Addressables 地址；加载/卸载必须走 `CoreMgr.Res`（有引用计数），禁止直接调 Addressables API
